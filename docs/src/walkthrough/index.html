How can we efficiently verify robustness to adversarial examples?

Can any change within the allowed pixel range make another digit tie or win? A mixed-integer program (MIP) can search for such an image. We’ll use a two-pixel network to see what simpler checks can prove, then look at how often they save a solver call on handwritten digits.

A neural network that classifies images assigns a score, or logit, to each possible label. Suppose it correctly recognizes a handwritten 9. Could we make it predict a different digit by slightly perturbing the image?

In this explainer, we call any digit other than the true digit a rival. For a handwritten 9, the rivals are 0 through 8. We check them one at a time, starting with 0 as our target digit. The logit difference on the perturbed image is the score for 0 (the target logit) minus the score for 9 (the true logit). A difference of zero means 0 ties 9. A positive difference means 0 scores higher. We count a tie or a win as an adversarial example, so ruling out 0 means showing that the difference stays negative on every allowed image.

A network built from affine layers and rectified linear units (ReLUs) is piecewise affine in its input. A mixed-integer program (MIP) can encode this network exactly and search for an adversarial example. It needs a binary variable for a ReLU only when the allowed perturbations let that unit’s input take both positive and negative values.

Before solving the MIP, we bound each ReLU’s input over the allowed images. A relaxation replaces the ReLU’s exact rule with one that allows more outputs while keeping every output the ReLU can produce. For example, suppose the input ranges from −1 to 2. At input 0.5, the ReLU returns exactly 0.5. A relaxed rule can allow both 0.5 and 1 at that same input.

Picture the exact rule as a curve and the relaxed rule as a region containing it. We use convex regions, which contain the line segment joining any two of their points. Every allowed image still produces a permitted set of neuron outputs. Maximizing a rival’s logit difference over all the relaxed choices therefore gives an upper bound on what that rival can achieve in the original network.

If all nine upper bounds are negative, digit 9 scores higher than every rival on every allowed image. That proves the prediction is robust. If a bound leaves a rival in play, we look for an allowed perturbation on which that rival ties or beats 9. Once we check the scores on the original network and confirm the tie or win, we call that image a witness. One witness proves the prediction fails our robustness test.

Only undecided images go to the solver. Skipping the other solves saves verification time. In our MNIST results, 34 of 2,000 WK17a images reached the solver.

Two-pixel network: A toy model

Our toy classifier chooses between digits 9 and 0 using just two pixels. Both neurons, A and B, take the pixel brightness values x0 and x1 as inputs. Each digit’s score depends on both neurons’ outputs. With both pixels set to 0.50, the simplified network predicts 9. Move either pixel’s slider away from 0.50 to see how the two logits respond to one perturbed image.

Starting from 0.50 for both pixels, a pixel budget of 0.10 lets each pixel vary independently from 0.40 to 0.60. The outlined square on each map contains all those pairs and grows as the budget increases. The diamond marks the highest logit for the target digit, 0. The circle on digit 9’s map marks its lowest logit.

At the largest budget, 0.50, both pixels can vary anywhere from 0 to 1. Even so, digit 9’s logit stays higher than digit 0’s across the whole square. That happens in this two-pixel example. An MNIST classifier that correctly recognizes both digits must give 0 the higher logit on some images. How can we prove what happens in the toy model?

Interval arithmetic: start with a range for each digit’s logit

Can we prove that digit 9 always wins by bounding each logit separately over the allowed pixel values? Interval arithmetic carries the pixel ranges through the two hidden neurons to give a range for each logit. If digit 9’s lower bound is higher than digit 0’s upper bound, digit 9 wins on every allowed image.

Logit difference: compare both digits on the same image

The ranges from interval arithmetic can overlap even when digit 9 wins on every allowed image. For a tie, the two digits must have the same score on the same image.

For each pixel pair p in the allowed square X, the purple map shows digit 0’s logit minus digit 9’s. The two logits can rise or fall together while digit 9 stays ahead. If even the highest value on the map inside the square is negative, we can rule out digit 0.

The left side is the highest value on the purple map. If digit 0 could tie or beat digit 9 on even one allowed image, its logit difference would be zero or positive there. The maximum would be at least that large. So any negative upper bound on the left side rules out digit 0.

Interval arithmetic gives the right side. It subtracts digit 9’s lower bound (L9) from digit 0’s upper bound (U0). Those endpoints can be farther apart than the two logits on any single image. At ±0.301 their difference is at most , so this check leaves a tie open.

Back-substitution bounds: trace the logit difference back to the pixels

The purple map shows that digit 9 wins at every allowed pixel pair. Can we prove that from the network’s weights? A back-substitution bound starts with digit 0’s logit minus digit 9’s and works back to the pixels. At each ReLU, use an upper line if its coefficient is positive and a lower line if its coefficient is negative. This gives an upper bound on the difference for every allowed image.

When the input range crosses zero, our verifier chooses either 0 or z for hlower(z). Any slope α between 0 and 1 also gives a valid lower bound, αz≤h(z). Choosing slopes to tighten the final logit bound is a research question. Xu et al. optimize these slopes during verification.

Why does a backward pass help?

Back-substitution starts with the difference between the logits. It combines all the weights on a shared neuron before choosing a bounding line. Only the weight left after subtraction matters. A forward calculation can get the same bound if it keeps track of the shared neuron too.

A trained classifier combines many neuron outputs. To see what cancels, use just one neuron. Call its input z and its output h(z)=max(0,z). The rival scores wh(z) and the true digit scores h(z) + 0.25. Start with both weights at 1, then move the rival’s weight w above or below 1.

In the two-pixel network above, both directions give the same bound. Neuron B enters digit 0’s score with weight −0.0408 and digit 9’s with +0.0103. Bounding the first score from above and the second from below uses B’s lower line both times. Back-substitution combines the weights to get −0.0511 and uses that same line. Both calculations also use A’s upper line. The forward calculation preserves this agreement by keeping the bounds as functions of the same two pixels until it subtracts them, then maximizing the difference.

Candidate images: test a corner before calling the solver

Each rival still in contention gets one candidate image. To build it, read the pixel coefficients in that rival’s back-substitution bound. Set each pixel to its brightest allowed value if its coefficient is positive, or its darkest if negative. If the coefficient is exactly zero, either endpoint gives the same bound. We choose the darker one. Together these choices give one corner of the pixel box.

We test these images on the actual network, starting with the rival whose upper bound is highest. We stop as soon as any rival ties or beats the true digit. On WK17a image 63, two rivals remained, digits 5 and 8. The corner chosen for 5 gave a witness on the first try, so we skipped the corner for 8.

How often was a pixel coefficient exactly zero?

At a pixel budget of ±0.10, we counted the 784 coefficients for every rival left open by back-substitution. We found no exact zeros in either benchmark. WK17a had 181,888 pixel coefficients (232 open rivals across 156 images). RSL18a had 271,264 (346 across 65 images). These counts include corners skipped after an earlier witness.

If the true digit wins on every image we tried, another point in the box could still change the prediction. We then try projected gradient descent (PGD). For each remaining rival, PGD searches for an allowed image where that rival outscores the true digit. If the search finds none, a tighter bound may still rule out the rival.

Target LP: tighten the bound when back-substitution leaves a rival open

At ±0.389, back-substitution uses one lower line for neuron B and leaves digit 0 open. The ReLU relaxation used in Target LP keeps both lower bounds. B’s relaxed output h~B must be at least zero and at least its input.

The LP maximizes digit 0’s logit minus digit 9’s over the relaxed network. B has a negative coefficient in that difference, so raising its lower bound tightens the upper bound on the difference. With the same upper line for A, the LP maximum falls below zero. Digit 9 wins throughout the box. Target LP in PR #326

MNIST examples: compare bounds on handwritten digits

On the two-pixel plot we compared three upper bounds for one rival. A handwritten MNIST digit has 784 pixels and nine rivals. Choose one of four MNIST test images to compare the three bounds on the WK17a network at a pixel budget of ±0.10.

Start with image 19, a handwritten 3, and target digit 5. The circle shows the back-substitution bound for digit 5. The triangle shows its Target LP bound. A lower upper bound is tighter. Once it falls below zero, digit 5 cannot tie digit 3.

On image 63, a corner check finds an adversarial example. On image 584, Target LP leaves digit 8 open, and gradient search finds no adversarial example. The MIP proves that digit 2 wins throughout the allowed box.

Ruling out one rival settles a comparison. Certifying a handwritten digit takes nine such comparisons.
